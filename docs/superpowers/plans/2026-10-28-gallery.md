# Artellum Exhibition Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static, phone-first photo gallery (category list, masonry wall, lightbox) fed by folders of originals shrunk by one build script, hosted on GitHub Pages, plus a printable QR code.

**Architecture:** `originals/<category>/*.jpg` (git-ignored, stays on the laptop) is processed by `scripts/build.mjs` into `img/<category>/<name>-t.jpg` (thumb) and `-l.jpg` (large) and a `photos.json` manifest. The page (`index.html`, `style.css`, `app.js`) fetches `photos.json` and renders three hash-routed views. Build output is committed; Pages serves the repo root from `main`.

**Tech Stack:** Node 26 (ES modules, `node:test`), `sharp` (resize), `qrcode` (QR), plain HTML/CSS/JS in the browser, Google Fonts links.

**Spec:** `docs/superpowers/specs/2026-10-28-gallery-design.md`

## Global Constraints

- Static site, no framework, no database, no external storage; GitHub Pages from `main` root.
- Large image: 1600px on the long edge, JPEG, a few hundred KB. Thumbnail: 600px wide, JPEG. Originals never committed (`originals/` in `.gitignore`).
- Fonts (Google Fonts link): "Artellum" wordmark in `Homemade Apple` with small "handcraft" beside it; category names and titles in `Spectral`; small text in `Karla`.
- Colours from artellum `src/styles/tokens.css`: `--wall-quiet #e9e8e2` (page), `--ink #2c2a25`, `--ink-soft #4a473f`, `--rule #a9ab9f`, `--wall #c7cbbf`, `--frame-dark #3a2f28`.
- Look: thin `--rule` dividers between category rows, large serif category names, small sans count right-aligned, photos with no border or shadow. Mobile first.
- Photos only: no prices, cart or ordering. Optional caption = filename turned into a title (`before-the-rain.jpg` -> "Before the rain").
- Categories come from folder names, alphabetical unless `categories.json` (`{ "order": [slug...], "names": { slug: "Display" } }`) says otherwise.
- Wall images load lazily; the large image loads only when a photo is opened.
- Repo name `artellum-gallery`; URL `https://pranjalagg.github.io/artellum-gallery/`.
- Do not touch `../artellum` or `../boxofgoodies`.

## Review Focus

1. Phone photos carry EXIF rotation: a portrait shot must come out upright, not sideways.
2. iPhone photos may be HEIC: either converted, or skipped with a clear printed warning naming the file. Never a crash that hides the rest.
3. macOS junk (`.DS_Store`), non-image files and empty category folders must not appear in the gallery or break the build.
4. Re-running the build with hundreds of photos must skip unchanged files and remove outputs of deleted originals.
5. Browser Back from the large view returns to the wall (not off the site); an unknown `#/category` shows the home list.

Each line has its test in the task that owns the code (tasks 2, 4, 5).

### Task 1: Scaffold and naming helpers

**Files:**
- Create: `package.json`, `.gitignore`, `scripts/names.mjs`, `tests/names.test.mjs`
- Create: `categories.json` (`{ "order": [], "names": {} }`)

**Interfaces:**
- Produces (`scripts/names.mjs`):
  - `titleFromFilename(file: string): string` — drops extension, replaces `-`/`_` with spaces, capitalises first letter only. `"before-the-rain.JPG"` -> `"Before the rain"`.
  - `slugify(text: string): string` — lowercase, non-alphanumerics to `-`, trimmed, no repeats. `"Tea Lights!"` -> `"tea-lights"`.
  - `categoryLabel(slug: string, names: Record<string,string>): string` — `names[slug]` if set, else slug with dashes to spaces and first letter capitalised.
  - `orderCategories(slugs: string[], order: string[]): string[]` — slugs listed in `order` first (in that order, ignoring unknown), the rest alphabetical.

- [ ] **Step 2: Run** `node --test tests/` — Expected: FAIL (module not found).

### Task 2: Build pipeline (resize and manifest)

**Files:**
- Create: `scripts/build.mjs`, `tests/build.test.mjs`

**Interfaces:**
- Consumes: Task 1 helpers.
- Produces:
  - `build({ src, out, categoriesFile }): Promise<Report>` exported from `scripts/build.mjs`; the CLI part runs only when the file is executed directly, reading `--src` (default `originals`), `--out` (default `.`).
  - `Report = { processed: number, skipped: number, removed: number, warnings: string[] }`.
  - Output: `<out>/img/<category-slug>/<photo-slug>-t.jpg` (600px wide), `-l.jpg` (1600px long edge, never enlarged); `<out>/photos.json` shaped
    `{ "categories": [ { "slug": "paintings", "name": "Paintings", "photos": [ { "id": "before-the-rain", "title": "Before the rain", "thumb": "img/paintings/before-the-rain-t.jpg", "large": "img/paintings/before-the-rain-l.jpg", "w": 1200, "h": 1600 } ] } ] }` where `w`/`h` are the thumb's dimensions (used to reserve space before load). Photos within a category sorted by filename.

- [ ] **Step 1: Write failing tests** in `tests/build.test.mjs`, generating tiny fixture images with `sharp` into a temp dir (`os.tmpdir()` + `mkdtemp`):
  - `test("resizes large to 1600 long edge and thumb to 600 wide")`: a 3000x2000 fixture gives large 1600x1067 and thumb 600x400; a 800x600 fixture is not enlarged (large stays 800x600).
  - `test("applies EXIF rotation")`: a fixture 400x200 with EXIF orientation 6 produces large of 200x400 (portrait) and manifest `w` < `h`.
  - `test("ignores junk")`: `.DS_Store`, `notes.txt` and an empty category folder produce no photo entries and no category entry.
  - `test("unreadable or unsupported file is a warning, not a crash")`: a text file renamed `bad.jpg` gives a warning naming `bad.jpg`, and other photos still build.
  - `test("heic is converted or warned about by name")`: skip this test (with a `t.skip` reason) when sharp reports no `heif` input support; otherwise assert it converts.
  - `test("second run skips unchanged and removes deleted")`: after one build, a second run reports `processed: 0`, `skipped: n`; deleting an original then rebuilding reports `removed: 2` per photo and its outputs and manifest entry are gone.
  - `test("slug collisions get a numeric suffix")`: `My Photo.jpg` and `my-photo.png` in one category yield ids `my-photo` and `my-photo-2`.
  - `test("categories.json sets names and order")`.
- [ ] **Step 2: Run** `node --test tests/build.test.mjs` — Expected: FAIL.
- [ ] **Step 3: Implement `build`.** Accept extensions case-insensitively: jpg, jpeg, png, webp, heic, heif. Use `sharp(file).rotate()` then resize `fit: "inside"`, `withoutEnlargement: true`, JPEG quality about 80, progressive. Skip a photo when both outputs exist and are newer than the source mtime. Print a one-line summary and each warning in the CLI.
- [ ] **Step 4: Run** `npm test` — Expected: all PASS.
- [ ] **Step 5: Commit** (`feat: photo build pipeline`).

### Task 4: Page shell, category list, wall

**Files:**
- Create: `index.html`, `style.css`, `app.js`, `route.js`, `tests/route.test.mjs`

**Interfaces:**
- Produces (`route.js`, plain ES module also imported by tests):
  - `parseRoute(hash: string, slugs: string[]): { view: "home" } | { view: "category", slug: string } | { view: "photo", slug: string, id: string }` — `""`, `"#/"`, unknown slug -> home; `"#/paintings"` -> category; `"#/paintings/before-the-rain"` -> photo (id is not validated here).
  - `routeHref(r): string` is the inverse (`{view:"home"}` -> `"#/"`).
- `app.js` fetches `photos.json` once, listens to `hashchange`, renders into `<main id="app">`. A `renderPhoto(category, id)` hook is left for Task 5 (home and category views must already work without it).
